# JAR 兼容下一阶段方案 — 2026-10-15

目标：让安卓可用的代表性 JAR 在 NAS 上完成初始化、首页、分类、筛选、分页、搜索、详情和播放解析结果返回，并交付同一最终版本的完整回测记录。播放器界面、媒体下载、解码和转码继续后置。本文件是执行方案；制定方案期间不启动采集、模拟器或 NAS 服务。

当前代码基于 `bb43093`、`56d1272`，已通过 497 项测试。当前 NAS 镜像为 `tvbox-core:linux-amd64-art-complete-20261015`，ID 为 `sha256:f2f6208a737bd3cfb1826a5059623e1c59d57ce8687590af869d5168bded9318`。

现有 114 份制品的历史矩阵加修复跟进，可拆成 93 份有加载成功证据、11 份有效 JAR 加载失败、7 份加载未知，以及 3 份获取内容无效。该集合包含不同轮次；最终镜像只复测了四个修复样本。609 个 ready API/ext 入口也只代表初始化成功，搜索尚未纳入实际 ART 对照。旧私有配置、JAR 和响应已按环境规则清理，下一轮必须重新捕获，不能假称原字节仍在。

按以下五轮推进，每轮都有独立交付和完成条件。

第三轮的初始排查顺序已经确定：

1. **保护初始化 4 份**：潇洒 `65be8df8bfa6…`、天神 `a9dce1158db8…`、宝盒 2 线 `1ac653e6140a…`、月光宝盒 `a41f11e12267…`。先区分壳识别、绑定协议和版本差异。宝盒已有官方 APK 与固定源码 `ProtectedInitJar` 行为不同的证据，不能把它直接当成同基准下的 Linux 回归，也不统一切成 `declared` 绕过。
2. **原生 loader 1 份**：小虎斑 `cf928d087302…` 的 `NATIVE_GET_LOADER_NOT_READY`。记录真实 JNI/loader 调用过程和异常传播，先确认原版能否执行相同入口。
3. **其余 6 份一般执行失败**：南风及站点独立 JAR 等。重新取得匹配的原始配置和 JAR，采集受控堆栈、类/字段/方法描述符，再按共同原因合并修复。
4. **未知与 XBPQ 超时**：按下载、DEX 转换、初始化、业务 HTTP、JNI、关闭拆分阶段，记录线程栈和请求进度。先重复原预算，单独记录延长预算的诊断；不能因 30 秒仍超时就判断不兼容，也不能一直增加全局超时。一个入口超时后，其它入口用独立 runtime 验证，避免后续全部缺测。
5. **实例 native**：只有安卓可用样本实际调用到它、并阻断目标功能时才扩展桥接。届时用自有 ARM 用例验证两个不同实例的 receiver、状态、回调、返回值和异常；未调用的附带 SDK native 继续保留原声明。

对照规则固定如下：

- 继续保留 `ab11d289…` 固定源码基准，官方 `d5f5006…` APK 的产品观察单列。版本行为差异须写独立用例；必要时在 ART 编译运行固定源码的方法探针，并明确它不是原版 APK。默认行为不通过无版本标记的开关改变。
- 加载预算、调用顺序、偏好和应用数据在两端明确记录。主矩阵沿用既有预算；更宽的诊断预算单列。新轮次同输入的旧/新镜像比较与历史跨轮观察分别报告。
- 对可配置的源和自有用例，用本地固定 HTTP 字节验证编码、重定向、Cookie、错误和超时。不能冻结的第三方接口保留为在线观察，不声称已经确定性回放。
- 参数和响应在同一比较程序中重算哈希。PanConfig 的图像、状态文字和详情内容分别验证；允许记录宿主渲染差异，但不通过删除不同字段把方法计为完全一致。
- JAR 数、API/ext 变体数、实际调用方法数分别统计；双方失败与未执行不计通过。每种机制至少一个代表是首批覆盖门槛，不代表该机制的所有 JAR 都兼容。

每轮依次执行“固定输入 → Android/NAS 对照 → 最小用例 → 修复 → 定点验证”；最后进行完整矩阵。代表样本的成功链路与错误样本的失败阶段都要可复现。当前没有足够依据承诺所有 JAR 或某个兼容百分比，阶段结论以实际执行分母为准。

环境沿用现有项目 SDK、JDK、dex2jar、原生库和 NAS Docker 镜像。重新创建任务专用 AVD、目录和测试服务，不安装重复环境；不改变原有四个 NAS 服务。本轮冻结输入在 Android 对照、修复及最后完整复测结束前保留为任务测试输入，记录用途、占用和清理时点，避免子步骤之间丢失已固定字节。每次测试结束即停止临时服务；整体验证完成后清理私有原始数据、失败输入和临时缓存，保留可公开的哈希、合成用例和报告。

首个交付是第一轮的完整矩阵、历史 SHA 对应关系和失败优先队列。它将给后续修复提供同一版本、同一输入的起点。
