# JSON／XML接口源 Linux/NAS 接入 — 2026-10-16

已完成下一项：将 type1 JSON CMS、type0 XML CMS 接到正式 Linux 订阅会话。首页、推荐、分类／分页／筛选、搜索、详情和播放元数据不再误入 type3 的JAR执行路径。Python、type4和播放器继续后置。

复用既有 Node、JDK17、Gson和NAS基础镜像，没有安装新环境。JSON使用固定安卓源码的实际模型转换方法；XML使用JDK安全DOM绑定，保留CDATA、实体、多线路和分页属性，不引入XStream运行依赖。两者统一输出现有会话使用的vod JSON结构，保留原ID、空值和播放串。

固定源码协议的几个差异已保留：分类同时发送独立筛选字段与 `f` JSON；XML搜索只发 `wd`，JSON搜索附带 `ac=detail`；两种搜索签名不等于CMS搜索翻页；首页推荐用原列表ID补详情，没有套用桌面端“首页空则取首分类”的额外回退。

读取原保留订阅，固定4份完整原配置，没有替换API、key或ext。最终镜像先跑原首页首分类，再独立补测“推荐条目真实类型且存在于原分类表”的内容分类，两组结果分开。

每组40个预定步骤。首分类组23非空、7空、2个HTTP失败、2个响应解析失败、6未测；内容分类补测27非空、3个网络／HTTP失败、2个响应解析失败、8未测，没有将两组择优合并为兼容率。

首分类4个源和补测3个源完成断网响应重放，70个步骤槽位的参数／状态一致，其中54次成功返回字符串逐字节一致。HTTP403和XML错误体也作为原始失败重现。补测索尼在收到响应前断网，原记录缺少可冻结的失败事件，现有按响应顺序重放产生请求错配；该1例明确记为工具记录不足，不计CMS源失败或通过。原在线失败和错配记录都保留，没有重跑挑选成功来覆盖。

两类型还在最终NAS镜像上通过断网本地HTTP端到端用例：12次会话方法调用、10次HTTP请求，验证真实订阅分发、JSON/XML解析、参数、元数据与清理，未创建JAR／JS实例。直接媒体URL只产生 `parse` 决策和透传结果，未下载或播放媒体。
